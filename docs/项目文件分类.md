# 项目文件分类

## 需要上传到 GitHub 的源码

- `src/`：网页端业务源码。
- `public/`：图标、静态资源和 PWA 资源。
- `electron/`：Windows 客户端外壳源码。
- `cloudfunctions/worklog-api/`：CloudBase HTTP 云函数源码。部署时只把这个目录作为函数代码目录，不要从项目根目录带 `--dir` 发布。
- `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`：依赖和构建配置。
- `cloudbase.json`、`.env.example`：CloudBase 配置模板，不包含实际密钥。
- `vite.config.ts`、`tsconfig*.json`、`index.html`：前端构建配置。
- `README.md`、`docs/`：使用、部署和维护说明。
- `scripts/force-bootstrap-mode.cjs`：Windows 发布 HTTP 云函数时保留 `scf_bootstrap` 执行权限的部署辅助脚本，不包含密钥。

## 云端部署内容

部署 CloudBase 云函数时使用：

```text
cloudfunctions/worklog-api/
```

其中真正的启动入口是 `scf_bootstrap`，它启动 `server.mjs`。会话密钥、加密密钥、文件 ID 等服务端环境变量只配置在 CloudBase 控制台，不放进 GitHub。WPS App ID/Key 可以由用户在客户端填写，授权时通过 HTTPS 传给自己的云函数。

## 本地预览和本地客户端

- `dist/`：`pnpm build` 生成的网页预览产物。可以用 `pnpm preview` 预览，不需要上传到 GitHub。
- `release/工作脉络-win-x64/`：已生成的便携版 Windows 客户端目录，直接运行里面的 `工作脉络.exe`。
- `release/win-unpacked/`：Electron 的未安装调试版目录，主要用于排查客户端问题。
- `release/工作脉络-*-Setup.exe`：如果执行安装包构建，会生成可分发的 Windows 安装包。
- `node_modules/`：本机依赖缓存，只用于开发和打包。

## 构建过程中产生的文件

以下内容会被重新生成，不需要手动上传：

- `dist/`
- `release/`
- `node_modules/`
- `*.tsbuildinfo`
- `vite.config.js`、`vite.config.d.ts`
- 临时的 CloudBase CLI 启动文件或调试目录

`.gitignore` 已经忽略了主要构建产物。当前目录里若看到名称异常且为空的临时目录，也属于本地工具残留，不属于项目源码。

## 三种常用操作

### 本地网页预览

```powershell
pnpm dev
```

### 本地 Electron 客户端

```powershell
pnpm run client:start
```

如果 WPS 授权时选错账号，关闭并重新打开客户端会自动清除上一次未完成授权留下的 WPS Cookie 和网页缓存。这个恢复动作不会清理工作记录、IndexedDB、本地配置或 CloudBase 会话；首次配置窗口也提供“清除上次授权状态，重新登录”按钮。

### 重新生成 Windows 客户端

```powershell
pnpm run client:package   # 生成安装包
pnpm run client:dir       # 生成便携版目录
```

### 发布 CloudBase 云函数

请按 [部署到CloudBase.md](./部署到CloudBase.md) 中的函数目录命令发布。不要在项目根目录执行带 `--dir .\cloudfunctions\worklog-api` 的 HTTP 函数发布命令。
